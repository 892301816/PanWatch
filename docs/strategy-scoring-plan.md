# 买入、卖出双向评分与选股整合方案

日期：2026-11-17，2026-11-18 补充原机会发现的具体整合方式。状态：待用户确认，只做方案及交互演示；未修改产品代码或部署。此方案是对原机会发现整合建议的进一步调整。

## 一、原逻辑核对

原机会发现不是简单的条件计数。`strategy_engine.py` 的分解计算把基础候选分、Alpha、事件催化、计划质量、来源奖励、风险与拥挤扣分组合起来，再应用策略权重、市场环境修正及状态封顶。它适合排序，但不等同于个人规则满足率。旧分类标签也不等同于用户可编辑策略。

目前个人规则主要按买入全部满足、卖出任一命中、禁买优先执行，内部支持条件树及缺数据状态；不具有贯穿所有页面的自定义买卖双向评分。选股使用另一套快照过滤条件和 all/any 判断，尚未与个人策略共用完整评估结果。

当前实现可复用：77 因子目录及计算、26 原生模板、条件树、草稿和不可变版本、买卖检查证据、账户约束、回测执行和成本模型。不能只加两个分数标签，必须统一评分定义、版本和数据口径。

## 二、产品结构

保留现有主导航和策略中心，使用一个“交易方案”组织同一交易周期的纪律。每个方案有四部分：

1. 股票范围：引用已保存的选股方案、关注、持仓或指定股票池。
2. 买入策略：例如回踩修复、放量突破、低位转强，可以多条启用，每条单独编辑条件、权重、门槛。
3. 卖出策略：例如冲高衰退、趋势破坏、回撤止盈，可多条启用。需持仓成本的策略明确标记“需要账户持仓”。
4. 必须遵守的纪律：禁止买入、风险退出和账户执行约束。它们不参与普通加分，也不被高分抵消。

用户主要操作“方案”和里面的“买入/卖出策略”；因子、比较符与条件组仅在编辑某条策略时展开。默认一个账户明确使用一份已启用方案；个股覆盖范围显式展示，避免多个默认方案叠加而不知实际使用哪个。

## 三、评分契约

### 每条策略单独打分

第一版使用可解释的加权满足率：策略分 = 已满足条件权重之和 / 启用的评分条件总权重 × 100。默认可等权，允许用户修改；原始权重不要求手工凑到 100。第一版不同时引入模糊分、负权重和 AI 主观分。

- 每项说明条件、阈值、实际值、命中状态、权重、贡献分和数据时间。
- 条件组可用全部/任一满足，组作为一个评分项；重复技术指标可归为同组并限制组权重，避免相似条件重复刷分。
- 某条策略的入场前提可设“必须满足”。例如回踩策略的前提是存在回踩结构；不符合前提时，不应靠其他普通条件凑分达标。
- 禁买条件、强制风险退出和账户可执行性另列；这些不是普通权重项。

### 多条策略之间如何合并

推荐方向主分优先展示已达标策略中的最高分；没有达标策略时展示最高分及其门槛，并显示对应策略名称。其他策略保留各自得分和命中情况，不平均、不相加。

例如“买入 80 · 回踩修复；放量突破 25”，含义是回踩逻辑接近/达到它自己的门槛；不要求回踩与突破同时出现。卖出同样处理：一条明确退出逻辑不应被其他未触发策略平均稀释。

不同策略可设置不同门槛；判断是否达标必须逐条比较其自身门槛，不能只用最高原始分与某个统一门槛比较。列表主分优先展示已达标的最高分策略；若没有达标策略，再展示最高分，并写明距该策略门槛还差多少。支持数显示“达标 2/5 条策略”，不把条数自动加到分数。

买入分与卖出分分别表示各自条件的支持程度，不是上涨概率或收益率，也不相减为一个净分。同一股票、同一方案和数据时点可以同时两边高分，这种冲突应展示出来。

### 缺失数据

已知命中权重构成下界，尚未知的权重构成上界，展示“60–80 分，关键条件缺数据”。不能删掉缺失条件再缩小分母、造成虚假高分，也不能把缺失直接解释为未命中。

- 任一适用策略的已知下界已超过自身门槛，且其前提/硬纪律已确认，才能认为该策略评分达标。
- 上下界跨过门槛：待补数据；上界仍低于门槛：尚未达标。
- 多策略方向区间为各策略下界最大值至各策略上界最大值；逐策略判断仍使用各自门槛。
- 对需要持仓的规则，未持仓为“不适用”，不是零分。已有持仓但成本、持有时间缺失则是“数据不足”。

## 四、买卖冲突与操作优先级

| 情况 | 默认呈现 |
| --- | --- |
| 买入达标，卖出未触发 | 显示可进入买入/加仓检查；仍需核对账户与拟成交信息 |
| 买卖均未达标 | 未持仓显示等待；已持仓显示未触发当前买卖规则 |
| 卖出达标 | 已持仓进入减仓/退出检查；未持仓提示退出形态预警，不生成做空建议 |
| 买卖同时达标 | 明示冲突，默认不新增风险；已持仓优先检查退出依据 |
| 禁买命中 | 新买入和加仓不通过，即使买入分很高；不阻止合理卖出 |
| 强制风险退出触发 | 独立提示退出依据，不等卖出普通分数凑够；账户可卖数量等限制仍优先核对 |
| 账户约束不满足或必要数据未知 | 不显示为可执行，保留信号得分与不能执行的具体原因 |

卖出策略可指定适用哪些买入策略；默认通用风险退出覆盖全部，周期相关的普通卖出规则按所属方案或入场策略执行。回测与实盘检查采用同一映射。

## 五、页面和操作

### 策略中心

沿用当前界面，主入口调整为“交易方案、机会发现、回测与复盘”。一份方案详情默认只展开：选股范围、买入策略列表、卖出策略列表、交易纪律。

每条策略固定提供编辑、复制、停用、删除，显示用途和门槛。编辑时以自然语言条件行展示，如“收盘重新站上5日均线，权重30”；用户需要时再展开字段和公式。模板复制后变成自己的策略，可编辑。

保存只保存草稿；显示实时演算样例和受影响页面。回测不会自动启用；明确“启用此版本”后才改变实际检查。修改已启用方案会显示“草稿已修改，当前检查仍使用 vN”。

### 机会发现

取消当前上下两套独立结果区，统一为一份按市场和股票去重的列表。候选来源为系统发现、选股结果、关注和持仓；来源仅提供股票及发现信息，不先按旧分数淘汰用户可能需要的股票。

每行优先显示股票、买入分及对应策略、卖出/退出预警分、硬纪律状态、数据日期和检查操作。点击分数展开策略清单，再展开具体条件，不把几十项条件全部铺满首屏。

旧系统保留来源标签、新闻、市场环境和发现理由，放进详情；旧综合分可在高级详情查历史，不再作为新主分或与新分混合排序。默认排序先看硬纪律和数据是否可判断，再按用户选中的买入/卖出方向排序。

机会列表未选择账户时，卖出分只评估不依赖持仓的形态策略，并标注“未纳入持仓条件”；与账户持仓相关的策略显示不适用。进入持仓和操作检查后，按实际账户补齐成本、数量及持有条件，不把两种上下文伪装成完全相同的分数。

### 理财持仓与买卖检查

原持仓、关注、记账入口和账户管理保留。持仓行可查看同一版本的买入、卖出分；优先展示禁买、退出和数据异常提示，避免塞满操作按钮。

- 新买入：买入策略是否达标、是否有卖出预警、禁买与资金/仓位约束。
- 加仓：同一买入策略评估，再检查本次加仓后的仓位、资金和用户配置的加仓限制；不能仅因有浮亏就形成加仓理由。
- 减仓：卖出策略及风险退出证据，再检查可卖数量与减仓后仓位。
- 清仓：同一卖出证据，标明清仓意图及数量；分数本身不决定应卖几成。

打开弹窗带入股票、账户、方向和已启用方案；先给结论、主因和两个分数，随后是命中策略与逐条条件。修改价格/数量后重新核对，条件或数据版本变动会让旧结论过期。

不符合个人策略时，需明确记录偏离原因；实际已发生的成交继续可以如实记账，不能因规则不通过而阻止保存真实交易。检查、例外和成交保持关联，方便复盘情绪化操作。

### 原机会发现的具体整合方式（2026-11-18 补充）

直接将原机会发现升级为新评分的主界面，而非在旧列表上方额外添加一个个人策略检查区。保留候选收集，替换主要评估与交互：

`原市场/Agent候选 + 选股结果 + 关注 + 全部持仓 → 按市场和代码去重 → 统一买卖规则评估 → 一份机会列表 → 带入账户价量检查 → 成交与复盘`

| 原能力 | 整合处理 |
| --- | --- |
| 市场热榜、异动与Agent发现 | 保留采集，提供候选股票、发现时间和来源依据；不把旧系统建议直接当操作许可 |
| 旧7类策略标签 | 保留为来源/发现标签；确有明确计算规则的内容，可另做可复制编辑的预置策略。标签不能直接伪装成完整可回测规则 |
| 旧综合分和自动权重 | 不再作为主列表的个人分，不与新买卖分相加；可在详情保留历史系统评估，不自动修改个人规则权重 |
| 新闻、市场状态和发现理由 | 保留详情及必要提示；如要进入正式评分，须先定义可执行条件、时点和数据可用性 |
| 风险与持仓约束 | 映射为可解释的策略纪律及独立账户检查，不作为旧分数里看不见的扣分 |
| 旧全局统计与校准 | 移入高级详情；主列表统计去重股票数，信号条数单独注明，不混用 |

主界面顶部沿用当前账户，默认使用实际已启用方案，显示版本和数据日期；提供候选来源、看买入/看退出及扫描操作。未选择个人方案时仍能浏览候选，个人分显示未评估，不强迫先建策略才能看到股票。草稿演算放在明确的研究模式，不能覆盖实际操作检查版本。

一行股票合并多个来源，点击买入/卖出分先看到对应策略，再展开逐条条件；从该行进入买卖检查时携带股票及来源，账户和拟成交信息确认后重算，复用同一规则和证据模型。

需要改动后端候选入口：当前旧列表先按旧状态、排序及数量限制取信号，前端再去重。新流程不能先取旧Top120再套个人策略；应在旧最终分/观察状态淘汰之前接入候选，按来源分页收集并去重，评估后再按新规则排序分页。保留收集范围上限及来源说明，不能把市场热榜候选称为全市场扫描。

买入候选可以受所引用的选股范围约束；全部持仓必须单独强制纳入退出评估。某股票买入后不再符合选股条件时，仍必须留在持仓退出列表，避免最该处理的股票被过滤掉。

## 六、与选股联动

统一字段标识、单位、条件树、数据日期和因子计算，不让同一指标在选股和交易检查中出现两种口径。

选股解决“看哪些股票”，买卖策略解决“这些股票何时符合哪种操作条件”。用户可在选股结果中选择“使用交易方案检查”，也可在方案内引用已保存的选股方案作为股票范围。共同使用的条件只编辑一份版本，页面显示来源链接。

引用选股方案必须绑定其版本：选股方案修改后产生新草稿，提示关联方案可以升级，不静默改变当前交易方案。支持导入一次性的结果股票池；静态结果和动态筛选股票池必须区别标注。

仅当股票池过滤条件不依赖持仓、成本与拟成交价量时，才能用于全市场筛选。选股不等于操作检查已经通过。

回测动态股票池需要历史成员或按历史时点重新筛选；只有当前快照时，必须标记为固定样本研究，不能拿今天的候选集合冒充当时可交易股票池。

## 七、AI、模板和回测

AI 用于把描述转换成可执行的条件及权重草稿、解释命中与冲突、总结操作偏离；分数由确定的规则计算，AI 不临时改分，也不能用解释覆盖禁买或必要退出。无法量化的描述列为待确认，不能假装已执行。

“高开低走、次日没有修复”应拆成事件日、开盘相对前收、收盘相对日内高点回撤，以及下一交易日修复目标、判断时点、有效期和失效条件。用户确认用何种价格与幅度定义“修复”后，再进入正式规则。新闻或形态不能直接证明主力出货。

原26模板按可解释程度接入：可等价表达的拆成可编辑条件，复杂原生信号保留参数与运行入口并明确解释粒度，不把名称包装成完整可编辑规则。已有模板内部评分不能与外层新评分重复加分。

回测使用同一方案版本、买卖策略、权重、门槛和硬纪律。需要明确入场策略选择及同分优先级、卖出策略映射、信号确认时点、后续可成交时点、费用、可交易状态与重复触发控制。同根K线出现买卖触发时，按约定顺序处理，不用未知的日内路径推断成交。

报告增加买入/卖出得分曲线、信号对应的命中条件、触发退出原因和未执行原因；保留资产曲线、成交与风险指标。门槛先提供演示值供配置，不能称为经过验证的最优参数。

## 八、性能与兼容

本地快照先粗筛，再对候选批量计算所需因子；同一股票的行情和因子只加载一次，不能每条策略重复取数。首次进入展示上次结果和数据日期，扫描是可取消的后台任务，显示进度；全市场与候选池明确区分。

缓存按方案版本、股票/市场、数据时点、周期和评估口径区分；涉及账户的计算加入账户持仓指纹及拟成交信息，不能在不同账户之间误用结论。

已有启用策略保持原逻辑和版本，默认不自动切换。迁移到评分方案时保留买入全部满足、卖出任一命中的语义，使用兼容条件组或原判定适配；不能统一改成一个70分门槛。旧回测与操作记录保留原解释，不用新权重重算历史决策。

## 九、实施顺序与验收

1. 用户确认评分定义、页面操作和演示，暂不变更应用。
2. 实现统一评分与证据模型、版本和旧规则兼容；覆盖多策略合并、不同门槛、缺数据、禁买、强制退出、互相冲突及不同账户。
3. 做方案编辑与一份机会列表，接入持仓/加减仓检查和选股引用；核验相同版本、数据与上下文下所有入口的得分及证据一致。
4. 补齐回测与动态股票池范围说明、后台扫描和缓存；沿原部署流程备份并验收后发布。

优先验收：高买入分仍因“高开低走后未修复”禁止加仓；卖出高分不会被买入高分抵消；强制退出仍受账户可卖约束；缺数据不能造成虚假满分；草稿修改不会改变启用版本；实际成交可如实记账并记录偏离。

## 十、操作简化与整页预览（2026-11-18，待确认）

根据“操作还需要更加简单”的反馈，将日常操作收敛为：`看机会 → 点分数看原因 → 检查买卖`。主界面默认进入机会列表，不要求先选策略、权重或股票池。

- 主列表只分“买入机会”和“持仓提醒”。系统发现、选股结果和关注中的同一股票合并展示，来源显示在股票名称下；全部持仓始终纳入退出检查。
- 沿用当前账户及已启用规则。首页主要操作为“我的规则”和“更新机会”，来源细节及原系统评估放到股票详情。
- 每行保留买入分、卖出分及一句当前判断；点击分数查看命中条件。持仓行始终同时显示“加仓”和“减仓”。
- 规则集中为“买入依据”“卖出依据”“交易纪律”，直接提供编辑、添加和删除。默认权重隐藏在高级设置中，避免首次使用就要求分配权重。
