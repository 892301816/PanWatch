## 2026-11-20 盘中检测记录与选股、消息加载优化

用户追加要求：盘中检测设为每 10 分钟但感知只有几次；选股和消息页面进入慢。用户进一步确认 **有信号才推送，但能查看每轮检测记录**，因此保留信号通知及原 30 分钟同股通知间隔，没有改为每轮推送。

### 云端实测与原因

- 云端盘中检测配置为 `*/10 * * * *`、单股模式、`throttle_minutes=30`。11 月 19 日记录可见北京时间 09:30、09:40、09:50 等每 10 分钟执行，午休及盘后跳过。少的是通知，不是定时器只执行了几次。
- 原单股运行记录只保存“executed/skipped”汇总，通知尝试/发送字段未汇总到任务记录，前端也未展示 `result`，用户无法辨别未触发信号、节流或非交易时段。
- 调度修改接口此前只更新数据库，没有应用到运行中的 APScheduler，已保存计划可能要重启后才生效。
- 选股请求同步构建远程概念索引，并等待涨停池和历史涨停查询；全市场行情逐页串行抓取。迷你 K 线虽然本地优先，但缺数据会阻塞等待逐股远程回退。
- 消息接口每次进页面或切换筛选，都等待外部快讯及个股新闻聚合完毕。慢源会拖住整个响应。
- 检查时云端本地日 K 最新日期为 **2026-11-17**、约 **393 万条**；行情快照已到 **2026-11-19**。本地历史可直接使用，但不能冒充当天实时成交行情。

### 本次改动

- 每轮单股调度保存检测数、跳过数、推送状态、股票及简要分析，区分无信号、通知间隔、非交易时段、无行情和失败；Agent 页面直接显示这些记录。盘后跳过使用独立状态，避免被误认为完成了分析。
- 调度配置保存后在应用事件循环中只替换对应任务，不重启其他正在运行的 Agent；校验无效调度表达式。保留用户确认的“有信号才推送”。
- 选股首屏优先返回本地行情快照，无快照则用本地日 K；过期行情及概念索引在后台单任务更新，失败保留已有数据。全市场分页使用有限并发，抓取缺页不覆盖完整缓存。
- 默认筛选使用本地日 K 与缓存行情推算涨停统计，不再等待远程涨停池；封板资金等本地无法推算的字段保留缺失提示。页面显示真实数据日期及后台刷新状态，缓存刷新不改变历史行情日期。
- 选股页面在可见且处于 A 股交易时段时，每分钟重新读取筛选结果；自动刷新不新增选股历史。迷你图及详情小图走本地批量 OHLC，禁用逐股远程回退，并使用缓存行情合并当天 K 线；已有当日 K 线原位替换，成交量统一为手，不重复追加。
- 消息优先显示内存/本地新闻缓存，后台按 TTL 刷新并持久化缓存。一个源完成即可展示，不等待其他慢源；切换筛选复用原始消息，防止过时请求覆盖新条件。页面轮询状态，保留手动刷新与显式 AI 汇总入口，普通加载不调用 AI。
- 本次不补写旧检测明细，不凭当前持仓生成历史交易；截图同步修复与本次改动一起发布。

## 2026-11-20 截图换仓流水与 Agent 跟随同步

### 问题与云端核查

用户反馈持仓截图已更新理财持仓，但买入、卖出成交流水缺失，并要求换仓后 Agent 从旧股票迁移到新股票。2026-11-19 深夜至 11-20 凌晨通过专用部署身份只读核查云端，确认运行发布仍为 `20261117-213455-strategy-center`，421 个运行文件与发布清单一致。

- 云端 `trade_records` 中没有普利特（002324）及兴欣新材（001358）的记录；检查时已有 4 条交易流水，最新一条是 11 月 19 日的 ETF 截图加仓记录。
- 旧代码的新建持仓分支只写 `positions`，即使勾选生成流水也不会创建买入记录；“删除截图中未出现的持仓”分支直接删除旧仓，也不创建卖出记录。这两个分支可以解释换仓时持仓变了而流水缺失。
- 旧服务没有截图同步审计表，所查日志也未找到对应的截图提交请求，不能断言当次的选项与完整操作顺序。现存持仓已不同于用户举例，不能据此自动回填历史买卖或猜测迁移目标。

### 本次实现

- 持仓截图按差额覆盖新建、加仓、减仓、清仓四类估算流水。截图未出现的旧持仓单独预览，只有用户确认是完整截图并勾选清仓后才处理。
- 预览支持编辑统一记账日期与每行价格；成本差反推、现价估算、成本估算和用户核对价分别标识。流水备注保留截图来源、数量前后变化和价格口径，明确未计费用、并非券商逐笔成交。
- 首次为空账户建账时生成买入留痕但不回溯扣除历史现金；后续差额沿用交易现金计算。勾选同步可用资金时，最终以截图识别的可用资金为准。
- 默认开启前端“Agent 跟随持仓同步”。原持仓中的 Agent 配置复制到新持仓，完整清仓的旧股票解除绑定；保留调度、模型和通知配置。新股票已有同名配置不覆盖，其他账户仍持有旧股票则保留旧绑定。
- 多个来源对同名 Agent 使用不同配置时，不任意选取：保留原绑定并显示手动选择提示。没有原持仓绑定时不凭空推断模板；不会触发 Agent 执行或自动下单。
- 持仓、流水、资金、Agent 使用同一事务，失败全部回滚；预览状态变化返回 409 要求重新识别。重复同步相同快照不重复记账。A 股截图不会清理港美股持仓。
- 切换账户/截图类型清除旧预览；同步完成同时刷新持仓、流水和股票 Agent 列表。保留关闭流水/关闭 Agent 跟随的选项。
- 更新 `docs/trade-sync-guide.md`，说明完整截图、估算流水、迁移范围和历史补录边界。

- 默认进入机会列表，沿用当前账户与实际启用规则，不必每次先选策略、权重或股票池。

- 买卖检查自动带入股票、账户及规则版本，只填写价格和数量；价量改变后，旧检查失效。保存草稿与启用规则分开，草稿不影响实际判断。

## 2026-11-12 成交同步（短信/通知/交割单/助手）

## 2026-11-10 收盘后误发「盘中监测」

提交：`a2e2e2c`。

**现象**：16:30、17:30 仍收到【盘中监测】推送，内容是原始 JSON，标题列了 5 只股票。

**根因（自己引入的缩进事故）**：上一版把 `_lookup_stock_name` 以顶格方式插在类中间，提前结束了 `IntradayMonitorAgent` 的类体；其后的 `analyze` / `should_notify` / `run_single` / `_format_human_readable_content` 都被吞进这个函数里，类实际退化为继承 `BaseAgent`。

链路因此变成：

```
调度器 batch 分支 → BaseAgent.run → collect() 返回 skip_reason（日志有打印）
→ analyze 不再是盘中版，不短路 → 用「无股票数据」调用 AI
→ 模型返回 {"action":"hold",...} → 内容原样推送
→ should_notify 退回默认 True → 发送
```

**修复**：helper 移到类定义之前，恢复类方法；新增 2 项回归测试（类必须自带 analyze/should_notify/run_single；有 skip_reason 时不得调用 AI）。云端验证：收盘后 `collect` 返回 skip_reason、`analyze` 返回【盘中监测】跳过、`should_notify=False`。

**遗留建议**：该 Agent 的调度是 `*/30 * * * *`（全天每 30 分钟），夜间会空跑一轮（现在会静默跳过）；建议改为 `*/30 9-15 * * 1-5`。

## 2026-11-09 OpenCode 模型接入修复

提交：`793a87a`。

**现象**：在设置页测试 opencode 模型报 `Error code: 400 - {"type":"MissingSessionID", ...}`。

**原因**：OpenCode Zen/Go 网关自 2026-09 起强制要求每个请求带 `x-opencode-session`（稳定的会话 id），用于后端路由与提示缓存亲和；缺失直接 400。PanWatch 用的是标准 OpenAI SDK，默认不发这个头。

**修复**：`AIClient` 构造时按 host 判断 `opencode.ai`，自动注入 `x-opencode-session`；值按「服务商 + 模型」在进程内生成一次并复用，兼顾网关校验与缓存亲和性；支持显式传入 `session_id` 覆盖；非 opencode 服务商不受影响。

**验证**：未带头 → 400 MissingSessionID；带头 → 200 并返回内容；容器内用真实 Key 调用 `Say OK` 返回 `OK`；新增 4 项测试。

**补充（`97ed687`）**：设置页「测试」已通过，但「深度分析」仍报同一错误。原因是深度分析不走 `AIClient`，而是 TradingAgents 内部用 langchain `ChatOpenAI` 直连 `backend_url`。已在既有 `apply_compat_patches` 中加一个幂等补丁：构造 `ChatOpenAI` 时若 `base_url` 指向 opencode.ai，注入同一个 `x-opencode-session`。容器内实测 TA 的 `OpenAIClient(provider=openrouter)` 构建的 LLM 带上了该头，真实调用返回 `OK`。
