## 2026-11-12 成交同步（短信/通知/交割单/助手）

提交：`feat(portfolio): 成交同步接口与交割单导入`。使用说明见 `docs/trade-sync-guide.md`。

**背景**：同花顺没有对个人开放的交易数据接口，成交数据实际在券商。原流程只能在 PanWatch 手工「加仓/减仓」，漏记、错记成本高。这次把「外部成交 → 账本」做成统一入口，手机转发、交割单、助手口述都走同一套解析与落库。

**新增接口**
- `POST /api/portfolio/trades/ingest`：单笔成交。给 `text`（券商短信/推送原文）走宽容解析，或直接给 `action/symbol/quantity/price`；`dry_run` 只解析不写库。
- `POST /api/portfolio/trades/import/preview|commit`：交割单整文件预览（逐行查重/跳过）、确认导入（按成交时间排序）。
- 鉴权：登录 JWT 或带 `trade:write` scope 的 PAT；手机自动化用后者，不能读持仓、不能进 MCP。
- 幂等：优先券商成交编号（迁移 135 给 `trade_records` 加 `external_id`），否则用「账户+代码+方向+数量+价格+日期」复合键；重复请求返回 `duplicate: true`。

**解析**
- 短信/通知：方向、代码/名称、数量、价格、日期时间、佣金/印花税/过户费、成交编号、券商名；撤单/废单/申购/分红直接拒绝；名称-only 也支持（按名称匹配股票）。
- 交割单：自动识别 CSV/TSV/HTML 伪装 xls/xlsx/xls、UTF-8/GBK、前置账户信息行与合计行；按中文列名同义词映射；`发生金额` 与 `成交金额+费用` 两种口径都兼容；缺价格时用金额/数量反推。
- 落库复用 `wealth.execute_trade`：同一套费率、成本摊薄、现金变动；费用明细解析不到时按差额归到佣金，保证总费用与券商一致。

**入口**
- 理财工作台新增「交易同步」（右上角按钮 / 「管理」菜单 / 「记一笔」里直达）：选账户、创建同步令牌、粘贴短信试解析/确认记账、上传交割单预览/导入、curl 示例。
- 助手新增 `record_trade`（写入类，需批准）：直接说「29.5 买入 002943 200 股」即可记账。
- 脚本：`scripts/sync/statement_watch.py`（监听导出目录自动上传，标准库实现）、`scripts/sync/autojs_ths_trade.js`（AutoJs6 读同花顺成交页）。
- 文档：`docs/trade-sync-guide.md` 给出 Android 短信/通知（MacroDroid/Tasker）、iOS 快捷指令、AutoJs、交割单导出、桌面目录监听、助手记账的具体步骤与排错表。

**截图导入（视觉模型）**
- 「理财 → 交易同步 → 截图导入」支持上传/粘贴「持仓截图」或「成交截图」，由已配置的视觉模型识别成表格，预览核对后同步。
- 持仓截图只更新持仓数量/成本（不写交易流水、不动现金），预览显示与当前持仓的差异，可选“删除截图里没有的持仓”（默认关）；成交截图走交易流水与幂等逻辑。
- 图片本地压到最长边 1600px；服务端只把图片发给用户自己的 AI 服务，不落盘保留；模型不支持图片时给出明确提示。
- 已用本机 `deepseek-v4.1-flash` 实测：模拟持仓截图识别 3/3 行、成本/数量正确，预览与落库（临时账户）通过。

## 2026-11-12 买卖前 AI 体检、禁买规则与回测升级

提交：`c4142d8`。使用说明见 `docs/strategy-playbook-guide.md`。

**背景**：11-11 早上买入宇晶股份（002943）后亏约 4 个点。事后看 11-09 已经出现「涨了一段后放量高开低走」（开 33.38、高开 +8.06%、收 30.00、实体 -10.13%、量能 1.40 倍），11-10、11-11 都没收复 33.38，属未修复的弱势形态。旧版策略卡只有买入/卖出条件，表达不了「这种形态就算其他条件满足也不碰」，也没有在真实下单前强制检查。

**形态特征引擎（`src/modules/strategy/patterns.py`，新增）**
- 在原有 9 个字段上补 8 个：近 20 日涨跌幅、开盘跳空、日内实体、上影线、收盘位置、连续跌破 5 日线天数、当日放量高开低走、放量高开低走后未修复天数。
- 「放量高开低走」= 高开 ≥ 2% + 实体 ≤ -3% + 收跌 + 量能 ≥ 1.3 倍；「修复」= 之后任一交易日收盘 ≥ 事件日开盘价 × 0.995，20 个交易日内未修复则 `gap_drop_days` 递增。
- 特征只用当日及以前数据；`diagnose()` 同步给出形态标签、白话说明与风险提示，供界面和 AI 共用。

**禁买规则**
- `strategy_playbooks` 新增 `avoid_conditions`（迁移 134，默认空数组），语义「任一命中即不买」，优先级在卖出之后、买入之前；未配置时行为与旧版一致。
- 检查结论新增「禁止买入」；首页策略信号与持仓徽标新增「禁」标识。

**买卖前体检（`src/modules/strategy/gate.py` + `TradeGate.tsx`）**
- 接口 `POST /api/strategy/gate`：返回规则逐条对照、形态诊断、AI 意见与最终结论，缓存键为「标的 + 方向 + 日期 + 价格档 + 规则指纹」，TTL 180 秒。
- 规则是硬约束：策略不满足或禁买命中 → 不建议，AI 不能抬回可操作；规则满足时 AI 可因形态风险下调。未配置 AI 时只返回规则与形态结论。
- 加仓/减仓弹窗、添加持仓（建仓）弹窗打开即自动体检；结论为「不建议」时确认按钮禁用，勾选「我知道当前形态/策略不满足」后才可继续。
- 随手验证（真实 AI 已配置）：002943 在 11-11 收盘后返回「不建议」，AI 理由引用了 11-09 高开 +8.1%、实体 -10.1%、量能 1.4 倍、3 天未收复 33.38、跌破 5 日线 2 天。

**回测升级**

- 界面：曲线加坐标轴与日期刻度、0% 基准线；新增「套用模板」一键保存并回测；可编辑禁买条件；展示交易解读。

## 2026-11-10 收盘后误发「盘中监测」

提交：`a2e2e2c`。

**现象**：16:30、17:30 仍收到【盘中监测】推送，内容是原始 JSON，标题列了 5 只股票。

**根因（自己引入的缩进事故）**：上一版把 `_lookup_stock_name` 以顶格方式插在类中间，提前结束了 `IntradayMonitorAgent` 的类体；其后的 `analyze` / `should_notify` / `run_single` / `_format_human_readable_content` 都被吞进这个函数里，类实际退化为继承 `BaseAgent`。

链路因此变成：

```
调度器 batch 分支 → BaseAgent.run → collect() 返回 skip_reason（日志有打印）
→ analyze 不再是盘中版，不短路 → 用「无股票数据」调用 AI
→ 模型返回 {"action":"hold",...} → 内容原样推送
→ should_notify 退回默认 True → 发送
```

**修复**：helper 移到类定义之前，恢复类方法；新增 2 项回归测试（类必须自带 analyze/should_notify/run_single；有 skip_reason 时不得调用 AI）。云端验证：收盘后 `collect` 返回 skip_reason、`analyze` 返回【盘中监测】跳过、`should_notify=False`。

**遗留建议**：该 Agent 的调度是 `*/30 * * * *`（全天每 30 分钟），夜间会空跑一轮（现在会静默跳过）；建议改为 `*/30 9-15 * * 1-5`。

## 2026-11-09 OpenCode 模型接入修复

提交：`793a87a`。

**现象**：在设置页测试 opencode 模型报 `Error code: 400 - {"type":"MissingSessionID", ...}`。

**原因**：OpenCode Zen/Go 网关自 2026-09 起强制要求每个请求带 `x-opencode-session`（稳定的会话 id），用于后端路由与提示缓存亲和；缺失直接 400。PanWatch 用的是标准 OpenAI SDK，默认不发这个头。

**修复**：`AIClient` 构造时按 host 判断 `opencode.ai`，自动注入 `x-opencode-session`；值按「服务商 + 模型」在进程内生成一次并复用，兼顾网关校验与缓存亲和性；支持显式传入 `session_id` 覆盖；非 opencode 服务商不受影响。

**验证**：未带头 → 400 MissingSessionID；带头 → 200 并返回内容；容器内用真实 Key 调用 `Say OK` 返回 `OK`；新增 4 项测试。

**补充（`97ed687`）**：设置页「测试」已通过，但「深度分析」仍报同一错误。原因是深度分析不走 `AIClient`，而是 TradingAgents 内部用 langchain `ChatOpenAI` 直连 `backend_url`。已在既有 `apply_compat_patches` 中加一个幂等补丁：构造 `ChatOpenAI` 时若 `base_url` 指向 opencode.ai，注入同一个 `x-opencode-session`。容器内实测 TA 的 `OpenAIClient(provider=openrouter)` 构建的 LLM 带上了该头，真实调用返回 `OK`。

- 提供精简列与完整列切换；精简模式保留标的、现价、市值、盈亏、今日盈亏、持有计划和操作。
- “详情、加仓、减仓”直接显示于桌面与手机持仓行；加减仓同级可见，继续复用原有费用、成本、现金变更和交易记账表单。
- K 线、相关新闻、深度分析、Agent 配置/运行、风控、编辑/删除等通过具名“更多”菜单进入。
- 关注页保留市场、分组、预警、搜索、排序和研究操作；不展示持仓资产摘要或记账控件，也不把关注标的计入资产。

### 计划与上下文操作

- 账本、账户管理及全账户组合分析按需在侧栏打开。账户流水继承当前账户范围，也可在侧栏更改范围。
- 计划页保留新建定投、确认成交、删除功能，增加进行中/已暂停筛选和暂停/恢复；暂停计划仍可找到。
- 定投按启用状态和下次计划日期排列；到期待办能传递账户与计划 ID，打开原成交表单。
- 理财目标收为辅助摘要及编辑弹窗，不虚构应急金达成率、被动收入进度或真实净值曲线。
- 账户策略、费用、分红再投归账户设置；分红历史归统一账本。分红处理继续调用原全账户接口，界面明确提示范围。
- 组合 AI 分析明确覆盖全部账户，按需生成，不伪装成单账户或实时分析。
