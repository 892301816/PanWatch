# 2026-11-27 策略类型拆分与图表信号统一

## 背景

策略中心有三套并存的东西：26 个模板、Pine 脚本、条件表单。它们各自算信号、各自画图，导致：

- 图上买卖点来自脚本，回测成交来自条件，两边对不上
- 出现"没有买入就显示卖出"的孤立卖点
- 模板策略的买卖条件被合成成一行 `所选模板入场信号 = 是`，用户改不了
- 从模板创建的策略同时带脚本和条件，点"编辑"进哪个窗口全靠推断，经常进错

## 操作变化

### 1. 策略只有一种类型

`config.mode` 成为唯一类型来源：

| 类型 | 含义 | 编辑入口 |
|---|---|---|
| `conditions` | 条件为唯一真相，图表与回测都按条件计算 | 条件表单 |
| `script` | 脚本为唯一真相，图表与回测都按脚本计算 | Pine 编辑器 |

- 「我的策略」列表按类型分成**条件策略 / 脚本策略**两个标签
- 列表标题行标注该策略属于哪一类
- 「编辑规则」按类型自动进入对应编辑器
- 历史草稿的遗留脚本会移入 `config.legacy_script` 留档，不再参与信号与画线

### 2. 模板参数变成可编辑条件

模板的过滤参数不再以"奇怪的小参数"出现，而是翻译成标准条件行：

```
连板接力  →  买入条件：当日涨幅 ≥ 5%    连板数 ≥ 2 次
缩量回踩  →  买入条件：收盘价在 MA60 上方   量比 ≤ 0.8
```

- 条件行可增、删、改，模板只是"默认值"
- 算法窗口类参数（回看天数、RSI 周期）单独成「算法窗口（高级）」，明确标注不是条件
- 合成信号行（`template_entry/exit`）在打开时自动迁移为真实条件行

### 3. 图表与回测共用一套信号

新增 `apply_paired_markers()` 作为**唯一信号实现**（持仓状态机）：

```
空仓 + 买入条件全满足 → 买入信号
持仓 + 卖出/禁买命中  → 卖出信号
持仓中再出买入信号    → 忽略（不加仓，与回测一致）
```

图表接口、检查接口、回测三处都调用它，因此图上第一个标记必然是买入，不会再出现孤立卖出。

### 4. 涨停与连板口径对齐

涨停判定改为与 `tick-stock-panel` 一致：

```
涨停价 = 四舍五入(前收 × (1 + 板块涨跌幅))，按整数分计算
板块：.BJ → 30%；300/301/688/689 → 20%；其余 → 10%
涨停 = 收盘价 ≥ 涨停价；连板数 = 连续涨停累计，断板归零
```

### 5. 新增能力

- **条件 → Pine 导出**：条件编辑器里「生成 Pine 脚本」，能等价表达的字段翻译成 Pine，不能等价的写成注释并列出清单
- **图表工具栏策略下拉**：工作台工具条可以把图表切换到任意脚本/条件策略
- **字段补全**：新增 14 个条件字段（连板数、当日涨停、近60日涨停次数、换手率、年化波动率、20日动量、RSI(14)、布林带宽，以及 MA 上下方、金叉、多头排列、突破 MA20、MACD 金叉、布林突破、创N日新低、收盘高于昨收）

## 修复的问题

| 问题 | 原因 |
|---|---|
| 图上"没买先卖" | 图表接口逐根独立判断卖出，没过持仓状态机 |
| 「买入第 N 条字段不受支持」 | 校验字段表（`patterns.py`）与界面字段表（`playbooks.py`）不同步 |
| 「所选区间没有可完整判断的日期」 | 连板/换手字段在回测行里没有产出 |
| 「策略配置包含不支持的字段」 | `mode` / `legacy_script` 未加入配置白名单 |
| 脚本策略点编辑进条件表单 | `openWork` 把 `view` 写死为 `my`，且 `setEditing(true)` 覆盖了脚本分支 |
| 关闭脚本编辑器退出整个流程 | 关闭时未回到「我的策略」，且 URL 残留 `step=rules` 导致条件表单复现 |
| 刷新页面自动弹编辑器 | 一次性参数 `edit=1` 留在地址栏 |
| 图表标记与回测不一致 | 两处各自计算信号 |

## 验证

- 前端：`template-param-rows` + `strategy-center` 共 **18 项通过**
- 后端：`test_chart_studio` + `test_pine_engine` 共 **17 项通过**
- 真实账号（本地 8085）实测：
  - 脚本策略「双均线交叉」→ 编辑 → 只打开 Pine 编辑器，无条单表单
  - 关闭编辑器 → 回到「我的策略」弹窗
  - 刷新页面 → 不再自动弹窗
  - 条件策略编辑 → 条件表单
- 配对信号单测：`4B 5S 8B 9S 12B 13S …` 严格交替，9 买 9 卖

## 边界与已知限制

1. **脚本编辑器不是真正的子窗口**：关闭后是"返回我的策略并重新打开弹窗"，会有一次页面重建，不保留搜索词与滚动位置
2. **脚本模式数据面窄**：Pine 只有 OHLCV + `ta.*`，没有财务、涨停标记、换手率；因此条件回测与脚本回测结果不可比，界面上有提示但未做结果分区
3. **涨停判定近似**：ST 股 5% 板未处理（缺少股票名称）；前复权导致的除权日失真未处理；假涨停/炸板无法识别（没有盘口数据）
4. **算法窗口部分生效**：`n_day_low` 已支持按窗口重算，`platform_days` / `squeeze_days` 仍固定默认值
5. **存量数据未批量修正**：部分老策略的 `config.mode` 可能仍缺失，界面用"是否有脚本内容"兜底判断

## 追加：涨停家数口径修正（同日）

问题：涨停天梯显示 570 家，同花顺为 426 家。

排查：

- 本地推算用的是"涨幅 ≥ 阈值"近似（主板 9.5%、创业板 19%、北交所 29.5%），把没封板的强势股也算成了涨停
- 实测同一交易日：阈值近似 **519** 家，按涨停价精确判定 **437** 家

修正：

```python
涨停价 = ((前收×100四舍五入) × (1+板块比例)×100 四舍五入 + 50) // 100 / 100
涨停 = 收盘价 ≥ 涨停价
```

- 板块比例：300/301/688/689 → 20%，4/8/92 → 30%，其余 10%
- 移除 ST 5% 判断：本地快照名称滞后，曾把已摘帽个股按 5% 误判（多算 60 家）
- 影响 `_local_ladder`、实时候选集与历史行判定三处

结果：本地推算由 570 → **437**，与同花顺 426 的剩余差异来自北交所 2 家与新股/退市整理等口径。
